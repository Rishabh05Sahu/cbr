# ADR-0011: Call scripts: authoring, versions, targeting

- **Status:** Proposed. Implemented locally (uncommitted) on 2026-10-28; awaiting owner review. **The FR-057 script-panel slice (decisions 10–11) was closed by the owner as complete on 2026-10-29**; FR-080–082 stay blocked by G5.
- **Date:** 2026-10-28
- **Builds on:** [ADR-0004](ADR-0004-multi-tenancy-and-permissions.md). Migration `0014_call_scripts`.

## Context
Phase 3 slice 5 (owner approval 2026-10-28) covers call-script authoring and publishing: FR-095 (sections, sanitized rich text), FR-097 (versions, publish, archive) and FR-096 (targeting and matching, limited to its acceptance criteria). Out of scope: FR-057 (the lead-page drawer that would show suggestions), FR-060, FR-065, calling, outcomes, FR-098 and project targeting (projects arrive in Phase 5).

## Decisions

| # | Decision | Source / why | Enforcement / evidence |
|---|---|---|---|
| 1 | **Model:** `call_script` holds name, status (DRAFT, PUBLISHED, ARCHIVED), targeting and the live version pointer. `call_script_version` holds the content (JSON, at most 64 KB). Name and targeting are **not versioned**: they apply to the script immediately. | FR-097 versions the text agents read. Targeting is configuration; versioning it would make matching depend on which version is live. | Migration 0014; `modules/scripts` |
| 2 | **Sections:** opening, questions, pitch, closing, plus up to 30 objection/response pairs. Each section at most 5,000 characters. At most 200 scripts per organisation. | FR-095 | Module validation; integration tests |
| 3 | **One draft per script.** Editing a published script creates the next version as a draft; the live version stays visible to readers until the draft is published. Version numbers are consecutive per script. | FR-097 | Partial unique index; `call_script_version_insert_guard` (version_no = max + 1, script locked `FOR UPDATE`) |
| 4 | **Published versions are immutable.** Publishing stamps `published_at = now()` and must not change content in the same update. Archiving is final; an archived script accepts no new versions or edits. | FR-097: history must be trustworthy. | `call_script_version_guard`, `call_script_guard`; DB immutability tests run as `crm_app` |
| 5 | **Optimistic concurrency:** settings and archive use the script `version`; save and publish use the draft's `version`. A stale form gets a conflict message, not a silent overwrite. | Two admins editing at once | Concurrency integration test |
| 6 | **Rich text:** authors write lightweight markup (blank-line paragraphs, `- `/`* ` bullets, `1. `/`1) ` numbered lists, `**bold**`, `_italic_`). All input HTML is escaped first, then converted, then passed through `sanitize-html` **2.18.1** (exact pin) with the allowlist `p, br, strong, em, ul, ol, li`, no attributes, no URL schemes, and dangerous tags' contents discarded. The stored HTML is sanitized again when rendered. | FR-095. Markup avoids shipping a WYSIWYG editor; the double pass limits damage from a future bug or a row written outside the app. This **reduces** XSS risk; it does not eliminate it. | `rich-text.test.ts` (17 attack payloads, malformed markup, idempotence, tag smuggling); integration test that author HTML is shown as text |
| 7 | **Targeting** (FR-096): transaction types, property types, languages (two-letter codes, matching `lead.preferred_language`), lead sources (must exist in the org). An empty list means "any". | FR-096. Language is a code because the lead column is `^[a-z]{2}$`. | DB CHECK on `languages`; module validation; test that "Marathi" is refused in the app and by the DB (23514) |
| 8 | **Matching order:** a script matches when the lead satisfies every targeted dimension (a lead without a value fails that dimension). Order: more targeted dimensions first, then name A→Z ignoring case, then id. | FR-096 asks for a deterministic best match; the most specific script is the most relevant. | `matching.ts`; `matching.test.ts`; `suggestForLead` integration test |
| 9 | **Permissions:** `script.manage` (create, edit, publish, archive) for Owner and Admin only. `script.read` for Owner, Admin, Sales Manager and Sales Executive. HR and support roles have neither. Readers see only published scripts and their live/published versions; drafts and archived scripts are hidden. | Role matrix | `permissions.ts`; RLS policies with RESTRICTIVE role checks via `app.current_member_role()`; no DELETE grant; DB role-matrix test as `crm_app` |
| 10 | **Lead-page script panel (amended 2026-10-29, FR-057 script panel + FR-099):** the lead page shows a "Call script" card naming the best match, and an **Open script** button that opens a drawer (native modal `<dialog>`: focus kept inside, Esc or backdrop click closes it, focus returns to the button, no navigation). It lists up to 5 matches from `suggestForLead` in the decision 8 order, best match first, with a chooser between them. Content is rendered and sanitized on the server (decision 6). With no match, the card says so, names the lead details used (looking to, property type, language, source) and links to all scripts. Roles without `script.read` (HR, support access) see no card. No new targeting or matching rules. | FR-057 lists a script panel; FR-099 requires a drawer; FR-096 requires the lead page to suggest the best match. | `script-panel.tsx`; `script-panel.test.ts`; integration "lead-page script panel" (drafts, archived scripts and unpublished edits never shown; language match/mismatch/missing; scope, role matrix, other org); browser check at 390×844 and 1440×900 |
| 11 | **Contact restrictions in the panel:** a script is reading material and grants no permission to contact. The panel has no call, message or link-out actions (no `tel:`, `sms:`, `wa.me`). On a Do-Not-Contact lead the drawer repeats the restriction: a script does not permit calling or messaging; use it only if the person makes contact (inbound is still allowed, ADR-0014 Q1). On an invalid-number lead it says to check the number first. Showing a script never changes contact status. **Owner decision (2026-10-29):** the panel stays on DNC leads, for inbound contact. | ADR-0012 (DNC is a hard block on outbound contact), ADR-0014 Q1 | Unit test (notice, no contact links or forms); integration test (DNC/INVALID: suggestions returned, status and events unchanged); browser check |

## Known limitations
- FR-057's call actions (FR-080–082) are not built: they wait for G5. FR-098 (the script version shown is stored with an interaction) is built: ADR-0014 decision 16, migration 0019.
- The panel shows at most 5 matching scripts; the full list is at `/app/scripts`.
- Project targeting waits for Phase 5.
- FR-096 is a "Should"; only its acceptance criteria are covered.
- **Dependency upkeep:** `sanitize-html` and `@types/sanitize-html` are exact pins under the 7-day release-age policy. Security advisories for them must be watched and upgrades re-run against `rich-text.test.ts`.
- No preview of a draft for readers, no diff between versions, no restore of an old version (publish a new draft instead).
