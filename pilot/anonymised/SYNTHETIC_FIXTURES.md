# Synthetic fixtures in this folder (NOT brokerage exports)

| File                         | What it is                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `synthetic_pilot_leads.csv`  | **Generated test fixture.** Excel "CSV UTF-8" style (BOM, CRLF). 22 columns × 29 data rows                   |
| `synthetic_pilot_leads.xlsx` | **Generated test fixture.** Sheets `Read me` and `Leads`; the rows are on `Leads`. 21 columns × 29 data rows |

**Not real data.** These files are **not** anonymised exports from a real brokerage. Every value is fabricated:

- names `Synthetic Lead NNN`;
- email addresses under the reserved `example.test` domain;
- invented notes;
- mobile numbers in a made-up `90000…` series, used only for local tests and never to be contacted.

**Where they come from.** They are generated by `pnpm exec tsx scripts/pilot/generate-synthetic-fixtures.ts`, from `tests/support/pilot-fixture.ts`. That file also holds the expected outcome of every row, used by:

- `src/modules/imports/pilot-fixture.test.ts` (no database);
- `tests/integration/import-pilot-fixture.test.ts` (local `crm_test`).

**What they do not prove.** Passing these fixtures shows the importer handles the synthetic scenarios. It does **not** prove compatibility with a real brokerage's export format; that remains gate P6 in `docs/PHASE-2-M4-REPORT.md`.

**Housekeeping.** The `.gitignore` keeps both files out of Git. Delete them when they are no longer needed; they can be regenerated at any time.
